# 東方原曲ドラフト会議

最大12人で東方Projectの楽曲を取り合うゲームです。プロ野球のドラフト会議と同じく、指名が重なったら抽選、外れた人は外れた人同士で再指名します。ウェーバー制は使いません。参加者はそれぞれ自分の端末から参加します。

## ファイル

この3つだけです。フォルダは作らず、すべて同じ階層に並べてください。

```
server.js       サーバ本体。進行の判定も抽選もここで行います
index.html      ホストと参加者が見る画面
package.json    起動方法を書いたファイル
```

この README は上げても上げなくても構いません。

## Render に置く手順

### 1. GitHub に新しいリポジトリを作る

github.com にログインし、右上の + から New repository を選びます。

- Repository name: 好きな名前（例 `thpro-draft`）
- Public を選ぶ
- **Add a README file のチェックは外す**

Create repository を押します。

### 2. 3つのファイルを上げる

作成直後の画面にある `uploading an existing file` を押します。

エクスプローラーでフォルダを開き、**フォルダごとではなく、中の `server.js` `index.html` `package.json` の3つを選んで**ドラッグします。フォルダごと入れると階層がずれて起動しません。

下の Commit changes を押します。

### 3. 確認する

リポジトリのトップページに戻り、一覧に `server.js` `index.html` `package.json` が並んでいることを見てください。フォルダ名がひとつだけ並んでいる場合は入れ子になっています。そのフォルダを開いて中のファイルを削除し、やり直してください。

ここが今回いちばん間違えやすい箇所です。

### 4. Render で Web Service を作る

render.com に登録します。GitHub アカウントでログインすると連携が済んで楽です。

ダッシュボードで **New → Web Service** を選び、先ほどのリポジトリを指定します。

### 5. 設定を入れる

自動で入る欄もありますが、次の2つは必ず自分の目で確認してください。

| 項目 | 入れる値 |
| --- | --- |
| Language / Runtime | Node |
| Build Command | `npm install` |
| Start Command | `node server.js` |
| Instance Type | Free |
| Root Directory | 空のまま |

Start Command に別の文字列が入っていると、起動せずに落ちます。

Create Web Service を押すと、数分で `https://なにか.onrender.com` が発行されます。

### 6. 動かす

発行されたURLを開きます。「会議を開く」「会議に参加する」の2つが出れば成功です。

## 遊び方

1. ホストがURLを開き「ホストとして開く」を選び、参加人数・巡目数・重複時の決め方を設定して部屋を建てます。
2. 参加番号とQRコード、参加用リンクが出るので参加者へ共有します。参加者は自分の端末からペンネームを入力して入室します。
3. ホストが「指名を開始する」を押すと、参加者の画面に指名入力欄が出ます。
4. 参加者は曲を入力して提出します。今後の指名に参加しない場合は、この画面で「この会議で指名終了する」を選びます。指名終了した人は以後の巡から除外されます。
5. 現在参加している全員の提出が終わると、ホスト画面で指名が一人ずつ表示されます。ホストが「次の指名を表示」を押して順番に確認します。
6. 全員の指名を確認した後、曲ごとにホストが「単独指名」または「抽選」を決めます。重複曲を「単独指名」にした場合は、候補者から獲得者を選べます。「抽選」にした場合はホスト画面で抽選します。
7. すべての曲の扱いが決まったら「この結果で確定する」を押します。抽選で外れた人だけが次の再指名に進みます。終了していない参加者は次の巡でも指名できます。
8. 設定した巡目まで終わるか、参加者全員が「指名終了」を選択すると、その時点で会議終了です。終了後は参加者ごとに獲得楽曲をリザルト表示し、テキストでもコピーできます。

## 無料枠で気をつけること

- 15分ほどアクセスがないとサーバーが休眠します。復帰に30秒から1分かかるので、会議の5分前に一度URLを開いて起こしておいてください。会議中は参加者の画面が定期的に呼びかけるので休眠しません
- 部屋の状態はメモリ上だけにあります。休眠や再デプロイをはさむと部屋は消えます。消えた場合は建て直してください。画面にも「部屋が終了しています」と出ます
- 会議の最中に GitHub へファイルを上げ直さないでください。再デプロイが走って部屋が消えます

## 最新の進行仕様

- 全員の指名が提出されると、ホスト画面では最初に参加者名だけが表示されます。ホストが「この人の指名を表示」を押すと、その人の曲名が表示され、「次の指名へ」で次の参加者へ進みます。
- 全員の発表後、同じ曲の表記ゆれをまとめた「楽曲グループ」単位で、ホストが「単独指名」または「抽選群」を指定します。
- 例として「千年幻想郷」「1000年幻想郷」「せんねんげんそうきょー」は同じ楽曲グループとして扱います。
- 抽選群を確定すると抽選段階へ移り、抽選群ごとにホストが候補者から当選者を選択します。ランダム抽選ではなく、ホストが当選者を決める方式です。
- すべての楽曲グループについて結果が決まると確定し、外れた参加者だけが同じ巡の再指名に進みます。
- 「指名終了」を選択した参加者は以後の指名対象から外れます。全員が指名終了すると、その時点で巡数に関係なく会議を終了します。
- 会議終了後は、参加者ごとに獲得した楽曲と巡目をリザルト表示します。

## 仕様のメモ

- 曲名は表記ゆれを吸収して重複判定します。全角と半角、ひらがなとカタカナ、中黒や長音記号の有無、「ヴ」と「ブ」の違いは同じ曲とみなします。ただし別名義までは判定できないので、読み上げのときにホストが目を通してください
- すでに誰かが獲得した曲は指名できません
- 提出された曲名が見えるのはホストだけです。画面を共有するときのために、曲名を伏せるボタンがあります
- 通信が切れても、同じブラウザで開き直せば元の席に戻れます
- ホスト席はスマートフォンでも構いません
- 長時間使わなかった部屋は6時間で自動的に破棄されます

## 困ったとき

**Deploy failed / status 127 と出る**　Start Command が `node server.js` になっていません。Settings の Build & Deploy で直し、Manual Deploy から Deploy latest commit を押してください。

**Deploy failed / MODULE_NOT_FOUND と出る**　ファイルがフォルダの中に入っています。手順3を確認してください。Settings の Root Directory にそのフォルダ名を入れても直ります。

**最初のアクセスが返ってこない**　休眠からの復帰中です。30秒から1分ほど待ってから読み込み直してください。

**「部屋が見つかりません」と出る**　サーバーが再起動すると部屋は消えます。建て直してください。

## パソコンで直接動かす場合

Render を使わず、同じWi-Fiにいる人だけで遊ぶこともできます。Node.js 18 以上を入れて、フォルダの中でターミナルを開き `node server.js` と実行してください。表示されたアドレスのうち `192.168.…` のほうを各自が開きます。`server.js` をダブルクリックしても起動しません。
